## First slice dependency policy

Use Go standard library for configuration, domain, filters, inventory, fake provider, explain and preview. Selectively adapt the rclone glob compiler and directory inference, with full MIT notice and immutable origin; do not add `github.com/rclone/rclone` to the production module. Use installed Git and a separately pinned rclone reference only in development tests. Wails/frontend packaging and future SQLite/API/vault packages have separate dependency ownership and must be pinned/reviewed by their implementation slices.

The upstream module contains many declared requirements; declaration counts in the baseline are not linked binary size or a security score. No complete license/vulnerability inventory of its unused dependency graph was attempted. The selected standard-library-only extraction makes that unused graph unnecessary for the offline core. Pin dependency additions, document why they are needed, retain notices and review updates with tests; do not introduce automatic major-version upgrades.

## Acceptance boundary

This decision opens safe offline implementation after the source gate. It does not authorize real accounts, imports, cloud writes, deletion, automatic scheduling, or claim all dialects/platforms are validated. A working local explorer and shared engine remain mandatory next deliverables. The parent's implementation report records actual code and product tests separately from this audit.
